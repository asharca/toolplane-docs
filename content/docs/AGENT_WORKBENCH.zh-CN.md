# Agent 工作台与工具

本指南面向在 Work 中使用 Agent 的工作区成员，说明会话操作、可选工具与运行保护。以下能力随对应**应用 PR 合入后的版本**生效；发布文档不会为旧应用开启能力。请核对部署代码、已应用修订和所需镜像，本文不把代码契约等同于真实模型、浏览器或生产部署验收。

## 开始前：确认修订与权限

- 需要已启用的原生 Pi Agent、可用模型和 Docker 沙箱。历史运行时、未解析修订及归档会话不因此恢复执行。
- 设置编辑的是草稿；经过现有的准备、权限审核和应用流程后，才形成新的不可变修订。现有会话仍需显式升级，不会因为打开开关自动获得权限。具体流程见[运行时实现](./AGENT_RUNTIMES.zh-CN.md)。
- 工具权限取**会话固定修订与实时 Agent 授权的交集**：后来开启的草稿不能扩大旧会话权限，实时撤销可以拒绝后续平台调用。沙箱扩展关闭在下一轮准备时重载，不强行中断已经开始的工具。
- 同一 Agent 的会话共享持久沙箱，目录分离不是 shell 安全隔离。工具审批、流式规则和密钥混淆均不能替代容器、挂载与网络边界。

## 运行中插话与排队追问

在自己有权控制、已实际开始运行的 Work 或普通 Agent 会话中，继续输入纯文本：

| 操作 | 如何提交 | 何时生效 |
| --- | --- | --- |
| 插话 `steer` | Enter | 当前原生工具执行结束、下一次模型请求之前 |
| 排队追问 `follow_up` | Alt+Enter 或独立追问按钮 | 当前回答及其工具、插话全部完成后 |
| 换行 | Shift+Enter | 仅编辑草稿 |
| 清空待处理消息 | 队列中的清空操作 | 只移除全部尚未消费的消息，不能逐项撤回或撤回已消费输入 |

队列显示模式、文本和待处理数量。接受入队不等于已经写入用户历史；模型真正消费时，先保存此前完成的回答/工具，再保存新用户消息。Pi 输入扩展也可能直接处理输入，此时不会伪造用户消息。

限制与故障处理：

- 运行中排队只接受文本，不接受附件、引用；最多 32 条，单条最多 100,000 个 JS 字符，另有约 1 MiB 的控制协议限制。
- preparing/queued 不代表宿主已可接收输入。`AGENT_QUEUE_NOT_RUNNING`（409）时保留草稿，等待就绪或切回普通发送；容量满（429）时等待释放。
- 控制传输失败（502）可能已经接受输入，先观察队列与历史，不要盲目重发。只有当前执行账户可控制队列；频道观察者不能在控制台发送或清空。
- 插话和追问沿用**同一次任务准入**的模型、固定修订、权限、预算与剩余截止时间，不创建并发任务，不延长执行时限。
- 控制台未消费队列不是持久任务，停止或进程丢失后可能需要重新提交。频道普通文本有持久入站恢复路径，清空原生队列不等于丢弃已接收的频道消息，详见[消息平台](./AGENT_MESSAGING_PLATFORMS.zh-CN.md)。

## 编辑、重试与分支

仅普通原生 **Work 会话**提供以下操作；普通 Agent 聊天、频道、触发器、公开 API 和 A2A 会话不支持这组树编辑。会话及执行后代须已停止，排队、运行或取消中不能操作；历史、退役、未解析修订或归档 Work 只读。旧消息没有可信原生节点映射时，入口不可用，平台不会按文本猜测节点。

1. **编辑用户消息**：从该消息起替代当前分支的后续上下文，用新文本重新入队；文本 trim 后 1–20,000 字符。附件和本轮模型选择等原有非文本元数据保留，prompt 展开重新生成。
2. **重试最后一轮**：重新提交当前分支最后一条用户消息，保留附件、引用和模型选择。它是新执行，不是查询旧执行结果；不要重复点击。
3. **从消息分支**：可选择已映射的用户或 assistant 消息，创建同一 Agent、同一固定修订和包快照的新 Work，包含截至所选消息的上下文。成功后新分支保持空闲，不自动发送原问题；如要重新运行用户消息，显式重试或发送下一条输入。

**三者都只改变对话上下文，不回退文件，不撤销外部副作用。** 分支使用共享 Agent 沙箱中的新会话目录，不复制源目录的文件快照，历史附件/路径可能仍指向源目录。重新执行可能重复写文件、发请求或产生其他副作用。原生树与已替代历史保留，但普通 transcript 只展示当前分支，未新增完整审计历史浏览入口。

编辑/重试的“已排队”（202）不是原生执行成功；继续观察 Work 输出。忙碌时先等待或显式停止，缺少原生节点/会话文件时按错误恢复匹配工作卷，不从数据库消息拼造原生历史。分支文件操作与数据库不是同一事务，失败可能需要管理员查看清理日志；未完成分支不会开放执行。

## 查看文件 diff

展开工具过程中的 `edit` 结果，可查看工具确实提供的 unified diff、旧/新行号和增删行；长 diff 默认折叠，可展开滚动查看。实时输出和刷新后的历史使用相同展示。

- 只有真实 `patch` 才显示 diff，不从普通输出推算。`write` 通常没有 patch，旧记录也不回填。
- 每份 patch 最多 65,536 UTF-8 字节；“内容已截断”可能包括不完整 hunk/尾行，不能当作完整可应用补丁。
- diff 是工具返回的变更展示，不是文件系统或 Git 快照；失败工具仍保留错误状态，不能因看见 diff 就认定操作成功。

## 导出会话

在 Work 侧栏的会话操作菜单选择**导出**与格式。工作区成员可导出有真实 Conversation 的工作、普通 Agent、频道及触发器会话；公开 API 会话、无 Conversation 的 A2A-only context 和尚未创建完成的占位会话不提供此入口。

| 格式 | 内容与前提 |
| --- | --- |
| Markdown | 数据库已持久 transcript：正文、推理、附件名称/类型、工具输入输出摘要及子活动；历史/只读会话也可用。不嵌入附件字节或授权元数据 |
| JSONL（Pi） | Pi 原生当前分支，不是整棵会话树；需要运行中的沙箱和可读原生历史 |
| HTML | 由固定 Pi SDK 渲染已经脱敏的原生分支；不加载项目扩展或自定义 renderer，沙箱须已有所需 SDK |

运行中也可导出，但仅包含读取时已经持久化的部分，数据库 Markdown 与原生 JSONL/HTML 可能不同。导出不发模型请求、不执行用户工具、不自动启动沙箱、不联网安装 SDK，也不修改真实会话文件。下载文件与原生输入快照各有 **8 MiB** 上限，超限整体拒绝，HTML 可能比 JSONL 更早达到上限。

沙箱未运行或原生文件不可用时，启动已有沙箱后再试，或改选 Markdown；文件缺失不通过重放消息伪造历史。导出要求登录态或个人 API token 和工作区成员资格，不生成公开分享链接，不接受 Toolkit/public Agent token。

导出使用共享脱敏规则，额外匹配已登记环境凭据（包括保留的撤销历史值）、模型密钥和裸 JWT；这不是任意未知秘密识别。分享前仍须人工审阅，尤其是自行粘贴的未登记内容。

## 用 @ 引用 Agent

在已有 Work 会话输入框输入 `@`，在 **Agent** 分组按名称选择本地或远端目标；引用以可移除 chip 展示，并保存到消息。未绑定 Conversation/Work 的新建页不提供该目录，不会为了搜索隐式创建会话。

候选必须已在来源 Agent 的固定修订与实时出站目标策略中同时获准。本地目标是同工作区、非自身且可执行的 Agent；已审核的父子委派边不要求目标开启直接入站。远端还须启用并满足允许来源 Agent 等既有规则。目录仅按名称搜索，不搜索远端地址或卡片正文。

引用由服务端重新校验名称、目标种类与授权，并生成要求调用 `pi_a2a_submit` 的指令；**引用本身不启动任务、不授予权限、不更新修订**。模型仍需实际执行委派，预算、能力、并发、循环/深度和实时授权校验照常执行。选择后目标被撤销时，提交整体拒绝且不写入本轮消息；保留草稿，移除失效引用或重新选择，不自动升级会话。平台 Agent 委派与下面的沙箱内 `task` 不是同一种能力。

## 工具审批

在 Agent 设置的**工具审批**中选择模式，保存并按修订流程应用：

| 模式 | 需要询问的调用 |
| --- | --- |
| `off` | 默认不询问 |
| `write` | 写入和执行 |
| `exec` | 仅执行 |
| `all` | 所有工具 |

`read/grep/find/ls` 归读，`edit/write` 归写；`bash`、MCP 和其他工具归执行，未知工具保守归执行。按 **Pi 实际执行工具名**配置 `ask/allow/deny` 覆盖，优先于模式；MCP 用原生生成名称，不是显示别名。历史修订缺省关闭。

普通 Work/chat/control 根入口在界面显示待审批工具名、脱敏参数摘要及到期时间，批准或拒绝只针对这一次精确参数调用。没有“本会话总是允许”操作。批准后仍需当前租约、参数一致和单次消费校验；批准不等于已经执行。有效期待审批最多 32 条，最长 120 秒且可能受任务剩余时间缩短。过期、重复决定、权限撤销或通道失败均不能执行；拒绝/超时形成失败工具结果，模型可继续回答，不自动把整轮标为失败。

频道在原 chat/thread 使用短码审批，控制台卡片只读，步骤见[频道工具审批](./AGENT_MESSAGING_PLATFORMS.zh-CN.md#频道工具审批)。**A2A 根任务、委派后代和触发器属于无人值守入口，不弹人工审批，即使覆盖为 deny 也自动放行并记录审计。** 这项策略不能作为无人值守执行的 deny 安全闸；仍须依靠真实工具授权与沙箱边界。扩展直接执行 Node/网络/文件代码也不受工具审批隔离。

## 启用可选内置工具

在 Agent 设置的**内置工具**中按分类选择需要的可选工具，默认全部关闭，新建/克隆为新 Agent 不继承可选权限。保存完整选择后准备修订、确认新增权限并应用，再新建会话或显式升级现有会话。目录只展示已合入且有真实实现的注册项；仅部署可选工具框架时清单为空是正常行为，不表示下列工具已随框架自动提供。

| 分类 | 工具名称 | 作用与执行位置 |
| --- | --- | --- |
| 编排 | `task` | 同一沙箱中的并行 SDK 子会话 |
| 搜索 | `web_search`、`web_fetch` | 平台受控搜索、读取公开文本网页 |
| 上下文 | `memory_retain`、`memory_recall`、`memory_forget` | 平台数据库中的 Agent 记忆 |
| Shell | `eval` | 沙箱内持久 Python/JavaScript 代码单元 |
| 浏览器 | `browser` | 沙箱内 Chromium 页面操作与截图 |
| 搜索 | `lsp` | 沙箱内 TypeScript/JavaScript 与 Python 只读代码查询 |
| Shell | `debug` | 沙箱内启动 Python/Node 调试会话 |
| 上下文 | `checkpoint`、`rewind`、`context_notes` | 原生会话分支检查点、上下文回退与笔记 |

`optionalBuiltinTools` 是独立的 opt-in 列表，不能用默认工具的 `disabledBuiltinTools` 反向启用它。平台工具的模型名称沿现有 MCP 原生命名规则生成；权限标识与回调名称仍是表中注册名。工具级拒绝通常作为模型可读的失败工具结果，依赖准备失败则可能在回合开始前阻止发布或执行。镜像、额外依赖与故障处理见[沙箱](./SANDBOXES.zh-CN.md)和[运维部署](./RUNTIME_OPERATIONS.zh-CN.md#agent-工具镜像部署)。

### task：并行但不隔离文件

`task` 每批 1–8 项，填写各自 `id/description/prompt`，可附共享 `context`。子会话不继承父聊天历史，只接收系统/资源约束、共享上下文和本项任务；使用同一个已准入模型、工作目录和当前工具权限，去掉 `task`，不能再递归派生。无需开启 A2A 出站或切换 native 子 Agent 模式。

并发受固定/实时 `nativeSubagentPolicy.maxConcurrency` 较小值限制（配置范围 1–8），超出排队；深度最多一层。工具等待整批结果，不是后台任务，每项获得槽位后最多 300 秒，父取消级联取消。每项最终回答最多 20,000 JS 字符，失败项使用固定原因，成功项保留；部分失败不自动失败父回合，用量合计入父任务。

所有子会话共享文件，可能发生并发写冲突，不是独立 worktree/平台 Agent。它们保留磁盘 transcript，但没有持久子会话查询、恢复或追问 API；不要把它等同于带独立模型、修订和沙箱的[平台 Agent 委派](./AGENT_RUNTIMES.zh-CN.md#平台-agent-委派)。

### web_search 与 web_fetch

- `web_search({query, limit?})`：query 最多 500 字符，limit 1–10（默认 5）。优先使用当前任务确有授权、符合通用搜索 schema 的工作区 MCP 搜索部署；无可用部署时使用无密钥 Exa MCP。已选服务执行失败不会静默换提供者重试，结果是标题、URL、摘要，不保证有结果。
- `web_fetch({url, maxChars?})`：仅无内嵌凭据的 HTTP(S) **公网**页面，逐跳检查 DNS/地址，最多 5 次重定向；不带用户 Cookie、凭据或 runtime token。20 秒总时限、响应体 1 MiB、输出默认 20,000/最多 50,000 字符。仅接受支持的文本类型，不接受压缩或二进制，不执行网页 JS；超出响应大小失败，输出文本截断则明确标记。
- 平台工具出网与沙箱网络独立：沙箱断网不会关闭已授权的平台搜索，工具启用也不放开沙箱网络。私网白名单的 A2A 例外不适用于 `web_fetch`。
- 搜索总截止 25 秒，但在途第三方 MCP 请求仍由既有超时收束，不承诺远端取消。JS-only 页面、非通用搜索 schema 和不可识别提供者结果有明确失败边界；日志不捕获网页正文。

### eval：跨单元内存不是持久恢复

`eval` 一次执行一个单元，`language` 为 `python` 或 `javascript`，`code` 最多 256 KiB；`timeoutSeconds` 默认 30、范围 1–300，`reset:true` 仅重建当前语言内核。Python 需沙箱已有 `python3`，支持顶层 await；JavaScript 是 Node vm script，可用 `require`、等待末尾 Promise，但不是 Bun/TypeScript，不支持静态 import 或裸顶层 await，也没有 OMP 工具桥或安装 magics。

同一会话每种语言独立保留变量；普通代码异常不清空已赋值状态。空闲 15 分钟、宿主重启、崩溃、reset 或无法中断的超时会丢失变量，结果用 `stateReset/notice` 明示，不能当作恢复成功。同语言重叠调用返回 busy。输出最多 50 KiB，截断有标记；代码的线程、进程和磁盘副作用不回滚，内核不是 bash 之外的安全隔离域。

### browser：沙箱 Chromium，不是用户 Chrome

操作包括 `open/click/type/press/screenshot/text/evaluate/close`；type 在光标处插入而非自动清空，evaluate 是页面 JS 而非 Node。截图为 1024×768 viewport JPEG（最多 150 KiB，非全页），工具结果中可预览/放大/下载；文本与 evaluate 结果最多 16,000 字符并标明截断。

每会话一个浏览器，页面和临时 Cookie 在常驻宿主多轮中保留，空闲 5 分钟、close、宿主重载或重启后不恢复 profile。动作总时限 30 秒，取消/超时回收进程。没有用户 Chrome relay、远程 CDP 或真实用户浏览器登录态；截图中的可见秘密无法靠文本脱敏清除，大量截图还可能超过既有活动回放总限额。

需要含 Chromium 的镜像，旧/自定义镜像没有它时返回 `BROWSER_CHROMIUM_MISSING`，不自动安装。`isolated` 是允许出网的独立 bridge，`none` 才是断网；none 下 HTTP(S) open 被拒，file/data/about 仍可用，文件只见沙箱。Chromium 使用容器的安全边界，不额外提供浏览器 OS sandbox。部署见[沙箱默认镜像](./SANDBOXES.zh-CN.md#docker-linux)。

### lsp：五种只读查询

支持 `diagnostics/definition/references/hover/symbols`，只处理具体 TS/JS 或 Python 文件。输入 `line/col` 从 **1** 起，列按 UTF-16；结果标准 LSP range 从 **0** 起。文件须在会话 cwd 或可信 sharedDir 的真实路径子树内，单文件最多 1 MiB；外部标准库定位可能省略。无新鲜诊断结果不能当作“无错误”。

不支持 glob/全项目检查、编辑、重命名、code action、任意 LSP 请求、远程或自定义服务。结果最多 64 KiB，导航/顶层符号最多 200 项，省略与截断明确标记。服务按会话/语言复用，空闲 5 分钟或超时销毁；工具路径检查不隔离语言服务器内部解析器或 native bash。

先由运维准备独立 `lsp-tools` 镜像，离线校验并安装到独立工具目录，不改 SDK；依赖缺失/损坏会以 `PI_LSP_ARTIFACT_UNAVAILABLE/INVALID` 阻止准备或执行，不能绕过完整性校验。

### debug：调试本回合启动的程序

支持 Python/Node `launch`，以及设置断点、continue、step_over/in/out、stack、scopes、variables、evaluate、output、terminate。launch 在入口暂停；每会话最多一个活动调试会话，先 terminate 才能再次 launch。断点行从 1 起，恢复执行后旧 frame/变量引用不可依赖；evaluate **可以执行代码，不是只读**。

单动作超时默认 15 秒（1–60 秒），调试会话总上限 300 秒，输出与单次结果各有 64 KiB 上限。同一用户回合内可多次交互，整个 Agent 回答结束即清理，不能跨下一条用户消息保留。无任意主机、端口、PID attach、远程调试或自定义适配器；宿主遭 SIGKILL/容器崩溃或程序主动脱离进程树时，不承诺应用清理能执行。

Python 需预装兼容 `python3` 及独立 debugpy 制品，Node 使用宿主已有 inspector。制品准备不写 SDK runtime，不在沙箱 pip/npm 安装；缺少依赖时返回固定失败，详见[运维部署](./RUNTIME_OPERATIONS.zh-CN.md#agent-工具镜像部署)。

## Agent 记忆

在 Agent 的**记忆**设置中搜索、手动添加或删除；管理操作无需启用模型工具，写入立即生效，也不发布修订。要让模型使用记忆，分别授权 `memory_retain`、`memory_recall`、`memory_forget`。

- 记忆按工作区 + Agent 归属，同一 Agent 跨会话/任务共享，其他 Agent（含父/子 Agent）不共享；不是全局记忆。
- retain 同步保存，下一次 recall 在同一回合即可读取。每 Agent 最多 500 条，每条最多 2,000 Unicode 码点；满额须先删除，不自动覆盖。
- recall 是字面子串/分词匹配，不是语义、向量或模糊搜索；默认最多 10、上限 20 条。空管理搜索返回全部（最多 500 条），有搜索时最多 20 条，页面总数是全部记忆数而非命中数。
- 记忆是**不可信历史数据，不是指令或权威**，不自动注入 system prompt。写入扫描命中凭据模式会拒绝，但无法识别所有自定义秘密，仍不得存凭据。
- 删除影响之后的召回，不追溯抹去已保存的会话/工具结果；来源 ID 也不是访问其他资源的授权。

## 加载项目指令文件

在 Agent 设置的系统提示词附近，用**加载项目指令文件（AGENTS.md）**控制 `contextFiles`；保存并按修订流程应用后，新会话或显式升级的会话才使用该值。新 Agent（含新建的复制草稿）默认开启，旧 Agent 和历史缺省修订保持关闭，不因升级应用自动开启。

把项目指令放在允许目录的 `AGENTS.override.md`、`AGENTS.md`、`AGENTS.MD`、`CLAUDE.md` 或 `CLAUDE.MD`，每目录按上述优先级只读取一个。宿主先读取自己的 agentDir，再读取 workspaceRoot 到当前 cwd 的祖先链；不扫描子目录、兄弟会话或界限外祖先，越界符号链接跳过。加载后进入原生 project_context，用量分类为 instructionFiles，发现范围详见[运行时实现](./AGENT_RUNTIMES.zh-CN.md#有界项目指令文件)。

文件是会话可写内容，不随修订冻结；修改后由原生 reload/新宿主重新发现，没有文件监控或递归发现保证。开关不是 shell 安全边界，也不把 OMP 的上下文发现设置自动映射过来。

## 主模型、兜底模型与角色模型

在 Agent 模型设置中为主模型配置**有序的 0–3 个兜底模型**，以及可清空的压缩、标题角色模型；角色未选时沿用主模型。审阅中核对完整顺序及角色，再应用到修订；现有会话须显式升级。所有目标必须是同工作区可用、具有凭据且被修订精确授权的 provider/model 对，不授予 provider 通配权限。

同模型按工作区重试次数耗尽后，仅对空流、流中断、5xx、429、超时、过载等瞬态失败按顺序切换；每个模型有自己的同模型重试次数。取消、任务总截止、鉴权或非瞬态 4xx 不兜底。**本轮只要开始过任何工具执行（包括失败或结果未知），就不再切换模型**，避免重放副作用；切换沿原生 continuation/recovery 继续，不重发用户 prompt。下一轮仍从准入主模型开始。

回答标签以实际应答模型为准，各模型消耗按各自工作区目录价格累计，失败尝试也可能有费用。压缩角色只服务手动/自动 compact，标题角色只服务会话命名，不永久改掉回答模型。外部提供者是否在线不在发布事务中探测，旧失败模型已流出的部分文本也没有新增撤回协议。实现依赖固定 SDK 的内部恢复/压缩边界，升级 SDK 必须重新验证，不能仅替换包版本。

## 月预算告警：提醒不是中途停机

在 Agent 用量设置配置月预算。达到或超过预算时，**新一轮准入**仍以 `AGENT_BUDGET_EXCEEDED` 拒绝；已经准入/运行的回合跨过预算不会被取消或变为失败。

网关观测到用量首次越线时，每任务记录一次提醒；Work 在该轮回复下显示持久告警，刷新仍可见，频道/触发器在最终回复后附通知。A2A 只记录 `agent.budget.exceeded` 审计事件，不改任务 artifact/回复。提醒展示首次越线的快照，不是实时计费计数器，也不会因最终用量向下校正而撤销。

网关暂记用量最终由 SDK 权威用量整体替换，不是再收一遍费用。提供者缺少 usage 或 usage 帧超限时可能只能在终态告警；观测失败不影响模型响应。跨 UTC 月的同一任务按首次网关观测用量所在月归集，不按每次请求拆月；实时通知仍受现有单进程观察架构限制。

## Advisor：建议而非授权

在 Agent 基础设置启用 advisor，选择同工作区的受支持模型、审查频率和最低严重度，保存并应用修订。关闭时不额外审查；历史修订缺省关闭。

- `each_tool_batch`：非空工具结果批次结束后审查，在下次主模型调用前插入建议。
- `final`：最终边界审查，达阈值时最多追加一次 follow-up，不循环审查自己的建议。
- 建议卡显示模型、频率、info/warning/critical 和文字，按严重度排序、按阈值过滤并去重。它是独立可见记录，不是主模型答复、批准回执或“主模型已经采纳”的证明，也不提供审批/主回复反馈按钮。

Advisor 只做有界文本增量审查，不读文件、不执行工具、不授予权限。单次最多等待 60 秒，取消立即释放等待；无效/截断输出、模型失败或建议持久化失败记录安全日志，不反向失败主任务。用量（失败审查已消耗的 token 也包括）计入任务预算并按审查模型价格计费；它不提供多个 advisor、独立审查会话或 fallback/retry。Work 显示依赖现有消息刷新周期，不承诺每条建议有独立实时 SSE。

## 流式规则

在 Agent 设置的**流式规则**中新增规则：稳定 ID、名称、目标、正则 source、动作和提示消息；可增删重排，保存后按修订流程应用，已有会话需升级。最多 50 条，pattern 最多 500、message 最多 2,000 UTF-16 字符。

| 目标 | 匹配与动作 |
| --- | --- |
| `assistant_text` | 单条 assistant 正文跨流块累积，不监控 thinking；仅允许 remind，不指定工具名 |
| `tool_call` | 可精确限定实际工具名，对 `JSON.stringify(input)` 匹配；remind 放行，block 在执行前阻止 |

pattern 使用无 flags 的 JS 正则 source（如 `危险操作`，不是 `/危险操作/i`）。提醒每条规则每个用户 prompt 最多一次，经真实 steer 交给模型；block 每次匹配都阻止，形成失败工具结果，**不自动终止整轮或回滚**。界面保留规则名称、提示和“提醒/已阻止”记录，不把触发记录重新当用户输入。

非法/命中风险启发式的表达式保存失败且不覆盖旧规则。建议使用简单明确正则：风险启发式可能拒绝安全模式，也不能证明所有表达式无 ReDoS。规则不提供参数重写、glob 工具名、AST/judge、磁盘规则发现或时间旅行；提醒不是正文过滤/撤回机制。

## 密钥混淆：仅覆盖已登记的环境凭据

Agent 基础设置中的**密钥混淆**在新建/复制的新 Agent 默认开启；旧 Agent 迁移后与历史缺省修订保持关闭，开启后须发布并显式升级旧会话。

网关发送给模型供应商前，将固定修订明确引用、实时仍有效、长度至少 8 个 JS 字符的环境凭据值替换成稳定 ASCII 标识符（如 `TP_SECRET_SERVICE_TOKEN_…`）。模型需原样复制标识符，ToolPlane 只在返回的结构化工具参数中还原真实值；用户可见正文/推理不反混淆。映射不持久化，也不增加访问权限。

**这不是任意环境变量扫描或未知密钥识别。** 不扫描文件、二进制附件和截图，不解码 URL/base64 等变体，不猜测模型改写/残缺的标识符，不重写既有本地会话或工具历史，不阻止工具经其他网络外传。凭据轮换、改名或 `AUTH_SECRET` 改变会改变标识符。已有运行沙箱不会仅因保存凭据或切换开关热更新环境，仍须遵守原有启动/重建生命周期。

## checkpoint、rewind、context_notes 与 /handoff

这些操作管理**模型上下文**，都不是文件、Git、进程或外部副作用回滚。

1. 同时明确授权 `checkpoint` 与 `rewind`（两个独立项，不自动互相开启）。模型调用 `checkpoint({goal})` 后，在整个成功工具批次结束处记下原生树节点；一次只能有一个活动 checkpoint，重启可恢复，没有列表或多检查点功能。
2. 探索后调用 `rewind({report})`，report 必须非空、最多 32,000 字符。最好单独一个工具批次调用。从紧接的模型请求开始以 checkpoint 分支 + report 替代探索结果，SDK 空闲后提交真实分支摘要。旧探索仍在原生树旧分支和 ToolPlane 已保存历史中，不从界面抹去。
3. 授权 `context_notes` 后用 add/list/remove 管理当前分支笔记；每次模型请求注入，压缩和重启保留，总 JSON 最多 16,384 UTF-8 字节。rewind 恢复 checkpoint 分支笔记并保留报告后的正常变更；不是跨会话或 Agent 共享记忆。
4. 在自己可操作的空闲非空会话，用 `/` 命令菜单提交 `/handoff`，可追加 focus instructions。它是始终可用的宿主命令，**不依赖上述可选工具**。通过原生 compact 将模型生成的交接文档作为摘要，目标章节为 Goal / Completed / In progress / Key files / Next steps；章节是自由 Markdown，不强制解析。最多保留最近三个完整用户回合且至少压缩最老回合，短会话沿 SDK 安全切点。

`/handoff` 使用当前已准入模型生成文档，不让生成过程执行工具，用量计入本轮；忙碌/空上下文拒绝。失败或取消不提交空文档，也不显示成功标记。成功的 rewind/handoff 在回复末尾显示可展开报告/摘要标记，原历史仍可见；标记不是授权或失败状态，也没有新增独立 Work 实时 SSE。
