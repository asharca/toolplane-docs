# 日志与审计

ToolPlane 会记录每一次 MCP 工具调用、每一个 A2A（Agent 之间）任务，以及重要的配置变更。
本文先说明怎样查看和排查，再说明日志保存多久、谁能看到；实现细节放在最后的“开发者参考”。

## 在哪里看日志

| 位置 | 能看到什么 | 谁能看 |
| --- | --- | --- |
| 侧边栏「日志」 | 本工作区的 **MCP 调用**、**A2A 任务**和用量 | 工作区成员 |
| MCP 详情 → 「MCP 调用日志」 | 只属于这个 MCP 服务的调用 | 工作区成员 |
| Agent 设置 → 「A2A 接入」 | 这个 Agent 参与的任务树、消息和进度 | 工作区成员 |
| Agent 设置 → 「频道」 → 日志 | 飞书、Telegram 等消息频道的运行日志 | 工作区成员 |
| 管理后台 → 「日志」 | 所有工作区的日志、系统健康、操作审计和导出 | 平台管理员 |

每个人只能看到自己所在工作区的日志；管理员在后台可以跨工作区查看。

## 查看 MCP 调用

列表里一行就是一次调用：

| 列 | 含义 |
| --- | --- |
| 工具 / 方法 | 调用的工具名，下方灰字是 MCP 方法（如 `tools/call`）。没有工具名时显示方法，都没有时显示“未知操作” |
| 服务 | 被调用的 MCP 服务 |
| 调用者 | 发起调用的用户、Agent 或 API 令牌；无法识别时显示“未知调用者” |
| 状态 | 成功或错误。MCP 服务返回了错误结果时，即使网络请求本身成功，也算错误 |
| 耗时、时间 | 时间按你的本地时区显示，鼠标悬停可看完整时间 |

**筛选**：可按时间范围（近 1 小时到 30 天，或自定义，最长 31 天）、服务、工具、方法、调用者类型、
成功/错误、“仅慢调用”（默认超过 2000 ms）和关键字筛选。筛选条件会写进网址，复制网址就能把同一个
视图分享给同事。

**详情**：点击工具名进入详情页，可以看到：

- **参数**：以字段列表展示调用时传入的参数。
- **结果**：按 MCP 返回的内容类型展示——文本、图片、资源或资源链接；结构化结果和错误标记也会单独显示。
- **原始 JSON**：任意面板都可以切换到原始 JSON 并复制，方便贴给开发者。
- **事件时间线**：这次调用经过的环节，例如“网关请求”和发往 MCP 服务的实际请求。

## 查看 A2A 任务

A2A 任务是一个 Agent 交给另一个 Agent（或外部 Agent）的工作。列表里一行是一个完整任务：

- **发起方 → 接收方**、方向（入站 / 出站 / 内部协作）、当前状态、子任务数量和总耗时。
- 可按 Agent、方向、状态和关键字筛选。

点击进入详情，可以看到：

- **任务树**：任务拆分出的子任务，以及每个子任务由谁处理、状态如何。
- **消息与产物**：像聊天记录一样展示双方往来的消息和最终交付的文件或结果。
- **状态时间线**：从提交、执行、等待输入/授权到完成或失败的每一步。
- **原始协议 JSON**：需要排查协议问题时再展开。

任务的耗时从被接收开始算到最终完成，不是单个网络请求的耗时。

## 实时更新

MCP 调用和 A2A 任务列表默认**实时**显示新记录，无需刷新：

- 点 **暂停** 后列表不再跳动，方便仔细查看；期间会提示“N 条新记录”。
- 点 **继续** 后新记录插入到列表顶部。
- 实时推送只包含列表信息，参数和结果等正文仍需进入详情查看。

消息频道日志同样支持暂停与继续，并可按级别（调试 / 信息 / 警告 / 错误）和关键字筛选，或复制当前结果。

## 常见排查

### 某个工具调用失败

1. 在「日志 → MCP 调用」中把状态选为“错误”，必要时再选服务或工具。
2. 打开失败记录，红色文字是错误原因；“结果”里通常有 MCP 服务返回的具体错误。
3. 如果参数看起来不对，问题多半在调用方（Agent 提示词或客户端）；如果参数正常而结果报错，检查 MCP 服务的配置、
   环境变量和「运行时日志」。

### 调用很慢

勾选“仅慢调用”，按需调整阈值，看慢调用是否集中在某个服务或工具上。

### Agent 之间协作卡住了

在「日志 → A2A 任务」或 Agent 设置的「A2A 接入」中打开任务，看状态时间线停在哪一步：
“等待输入”或“等待授权”表示需要人回复或批准；“失败”时查看最后一条消息和错误信息。

### 详情里看不到参数或结果

页面会说明原因：

| 提示 | 原因 |
| --- | --- |
| 正文超过保留大小，已截断 | 单条正文最多保存 32 KiB，超出部分不保存；已保存的部分照常显示 |
| 正文已过期，元数据仍可查看 | 超过了正文保留期限 |
| 内容受访问策略限制 | 例如 Agent 的对话内容，只有管理员在诊断时才能查看 |
| 未记录正文或正文已不可用 | 请求未通过鉴权、被拒绝、目标服务未运行，或网络中断时没有收到响应，也可能是旧版本留下的记录 |

参数和结果按 JSON 原样显示，对象和数组可以逐层展开或收起，嵌套层数不限。

## 日志保存多久、谁能看到

| 内容 | 默认保留 |
| --- | --- |
| 日志记录（时间、状态、耗时、错误等） | 30 天 |
| MCP 与 A2A 的请求和响应正文（包括 Agent 会话中的 MCP 调用） | 与日志记录相同，默认 30 天 |
| Agent 对话内容（提示词与回复，仅管理员诊断采集时记录） | 最多 24 小时 |
| 操作审计 | 180 天 |

管理员可以在管理后台「日志 → 保留策略与诊断采集」中修改天数。修改只影响新产生的记录，已有记录不会延长。

关于隐私：

- 密码、API 密钥、Cookie、Authorization 请求头和常见令牌格式会在写入前被替换为 `[REDACTED]`。
- 业务文本本身（例如工具参数里的客户信息）**不会**被匿名化。请只让需要的人加入工作区。
- 每次查看正文都会写入审计记录，可以追溯谁在什么时候看过。
- 公开 Agent API 的请求内容从不记录。

## 管理员

### 健康概览与快捷排障

管理后台「日志」顶部的健康概览固定统计**所有工作区最近 15 分钟**，不受下面列表筛选的影响，点刷新获取最新快照。

- 每个日志来源分别统计错误/超时和拒绝次数；一次请求可能产生多条事件，所以事件数不等于请求数。
- “未观测到错误”只说明这段时间没有失败记录，不代表服务一定可用；ToolPlane 不会主动探测服务。
- MCP 部署异常指状态为失败，或本应运行却没有对应进程的部署；主动停止的不算。

推荐排查顺序：点击有异常的来源卡片 → 用“失败 / 超时 / 已拒绝”快捷筛选 → 查看错误聚合与最近出现时间 → 进入事件详情。

管理后台的「MCP 调用」和「A2A 任务」页签与工作区页面相同，只多了工作区列和工作区筛选。
「全部事件」「请求」「执行链」「运行时」页签显示的是底层事件，时间为 UTC。

### 诊断采集

排查疑难问题时，可以对某个工作区、MCP 部署或 Agent 开启 **15 分钟**的诊断采集，记录更多内部细节。
如需查看 Agent 的提示词和回复，必须单独勾选“Agent 内容采集”，这类内容最多保留 24 小时。
开启、停止和保留期变更都会写入审计。只在必要时开启，并限制可访问管理后台的人员。

### 导出与审计

- **导出 JSONL** 最多 1,000 条，只包含日志记录，不含请求和响应正文。导出本身也会写入审计。
- **操作审计**记录关键变更：用户角色与状态、系统设置、模型服务商凭据、API 令牌、插件来源与安装、插件下架与版本撤销等。
  审计写入失败时，对应的变更会被回滚。审计记录在应用内只能追加，但不能防范直接修改数据库的人。
- 用户和工作区详情页可以直接跳转到相关的事件与审计。

## 开发者参考

以下内容面向维护和二次开发 ToolPlane 的开发者。

### 数据存储

- `LogEvent`：可检索的元数据——时间、级别、来源（domain）、结果（outcome）、HTTP 状态、RPC 方法与工具名、耗时、
  错误类型与代码、各类资源 ID、请求 ID、trace/span ID，以及 MCP 调用 ID `callId`。
- `LogDetail`：可选的脱敏正文或错误堆栈，上限 32 KiB，带过期时间，随父事件级联删除。
- `AuditEvent`：操作者、动作、目标、前后变更和关联 ID；删除实体不会级联删除审计。
- A2A 任务账本（`A2AContext`、`A2ATask`、`A2AEvent`）独立于日志，按上下文保留期清理。账本先被清理时，任务详情只显示日志部分。

`httpStatus` 是传输层结果，`outcome` 是业务结果：HTTP 200 但 JSON-RPC 返回 `error` 或 `result.isError` 的 MCP 响应记为错误。
统计、平均值、P95 和小时分桶都在 Postgres 中计算。

### 埋点

- `withRequestLogging` 在鉴权前包裹 JSON/网关处理器，生成服务端请求 ID，记录早期失败；SSE 的完成、失败、取消各记录一次。
  不记录原始 URL、请求头或请求体。
- `withLogContext` 用 AsyncLocalStorage 传递 trace、身份和 `callId`；调用方提供的请求 ID 不被信任。Work 等后台执行使用
  独立上下文，不继承其他请求的操作者。
- MCP 网关为每个 JSON-RPC 请求生成 `callId`，发往上游的 `mcp.rpc` 继承它，因此网关记录与实际传输记录一一对应；
  没有 `callId` 的历史记录按工作区、部署、方法和工具推断关联。
- `recordEvent` 同时向 stderr 输出脱敏 JSON。数据库写入为尽力而为：每个 worker 最多 32 个在途写入，失败或过载时丢弃并计数，
  不影响业务请求。需要更强持久性时，用外部日志收集器采集 stderr。
- 关键数据库变更在同一事务中调用 `writeAudit`；涉及外部进程的删除先记录意图，再记录结果。

### 正文采集策略

事件声明 `metadata-only`（默认）、`diagnostic`、`agent-content`、`request-response` 或 `forbidden`：

- 只有成功鉴权的请求边界使用 `request-response`。具备工作区和部署范围的 `gateway.request` 与 `mcp.rpc`
  （包括 Agent 会话中发起的调用），以及已授权的 A2A 请求与结算事件，默认保存脱敏正文，保留 `min(detailDays, eventDays)` 天，
  工作区成员可见；显式 `suppressPayload` 或 `forbidden` 时不保存。协议正文不限嵌套层数，只受 32 KiB 上限约束。
- 其他 `agent-content`（如 Agent 的提示词、回复和内置工具输入输出）需要管理员为指定资源显式开启 `includeAgentContent`，最多保留 24 小时。
- 父上下文的 `suppressPayload` 单向继承；`forbidden` 和公开 Endpoint 的禁止策略优先于任何采集开关。
- 响应读取最多 32 KiB 或 200 ms，不采集 SSE 流。工作区成员只能读取采集时带有许可标记的正文；历史未标记的正文只对管理员可见。
- 平台把 MCP 当作传输通道的内部调用（`@` 文件列表、知识库文档读写、沙箱文件浏览、经沙箱检查远程 MCP）记为 `mcp.internal`，
  不混入「MCP 调用」，在工作区「日志 → 平台内部调用」页签单独列出，正文与错误的采集和可见范围与 MCP 调用相同。
- 智能体每次调用工具（`bash`、`read`、`edit`、MCP 工具等）结束时记一条 `sandbox.tool`，含工具输入与输出（各约 20 KB 上限），
  在「日志 → 智能体工具调用」页签查看，工作区成员可见；智能体提示词、回复等其他内容仍需管理员诊断采集。
- 管理后台只记录元数据的事件不再显示“未记录正文”，只有存在正文或正文已过期、受限时才显示正文区域。
- 设置在每个 worker 内最多缓存 10 秒。启动钩子每 5 分钟在 Postgres advisory lock 下清理过期数据，每张表每次最多 10 批、每批 1,000 行。

### 接口

| 接口 | 说明 |
| --- | --- |
| `GET /api/v1/workspaces/{slug}/logs/mcp-calls`、`/mcp-calls/{id}` | MCP 调用列表（keyset 分页，每页 50 条）与详情 |
| `GET /api/v1/workspaces/{slug}/logs/a2a-tasks`、`/a2a-tasks/{taskId}` | A2A 根任务列表与详情 |
| `GET /api/v1/workspaces/{slug}/logs/stream?kind=mcp`（或 `kind=a2a`） | 实时推送（SSE），参数与列表筛选相同 |
| `/api/v1/admin/logs/...` | 管理员同构接口，可跨工作区 |

工作区接口使用个人 API 令牌或登录会话鉴权，并校验工作区成员身份；读取正文前必须成功写入 `logging.detail.viewed` 审计。
实时推送服务端每秒按 `(createdAt, id)` 游标查询数据库，多进程部署同样有效；每 15 秒发送心跳，单个连接最长 10 分钟，
浏览器自动带游标重连；推送内容不含正文。
