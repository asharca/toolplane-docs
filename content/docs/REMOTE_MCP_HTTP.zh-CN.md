# 远程 MCP：HTTP 兼容与传输风险


本文面向将 ToolPlane 连接到远程 MCP 服务的用户与管理员。远程 MCP 支持 `https://`（推荐）、`http://`，以及 1–65535 范围内的显式端口。JSON 配置中的 `"type": "http"` 表示 Streamable HTTP 传输，不代表地址必须使用明文 HTTP；HTTPS 地址仍使用这个 type。

## HTTP 示例

```json
{
  "mcpServers": {
    "internal-mcp": {
      "type": "http",
      "url": "http://mcp.example.com:8000/mcp",
      "allowUnsafeHttp": true
    }
  }
}
```

需要认证时，JSON 导入仍支持通过 `headers.Authorization` 使用 Bearer 认证。但凭据存入 ToolPlane 的受管变量，不代表它在上游 HTTP 网络链路上被加密。

## 用户必须知道的风险

**HTTP 不提供 TLS 加密、服务器身份校验或传输完整性保护。** ToolPlane 与远程 MCP 之间的 Bearer Token、其他认证请求头、工具参数和返回数据可能被窃听或篡改。泄露的凭据可能被盗用；篡改后的工具结果也可能影响 Agent 后续行为。

优先使用 HTTPS。确实需要 HTTP 时，只应在经过评估的可信隔离网络，或覆盖完整连接的加密隧道内使用。内网并非天然安全。避免通过明文 HTTP 发送生产凭据或敏感数据。

**ToolPlane 网页使用 HTTPS，不会保护 ToolPlane → 上游 MCP 的 HTTP 连接。** 浏览器的安全连接标志不能证明这段上游链路安全。

HTTP 连接必须在配置中显式设置 `allowUnsafeHttp: true`，确认明文传输风险；仅显示警告不代表已同意。JSON `type: "sse"` 选择旧版 SSE，`type: "http"` 选择 Streamable HTTP。两种传输均不自动切换，也不从 HTTPS 降级。HTTP bridge 启动时仍发出不含秘密的警告。

创建连接操作还要求安装操作者单独提交 `allowUnsafeHttp=true` 选择；下载配方或导入 JSON 中的同名声明不代表操作者同意。未确认的目录连接保持 `setup_required`，返回 `unsafeHttpConfirmationRequired`；既有连接可使用显式批准操作，并对重新计算的共享影响对象确认。批准不会自动调用业务工具。

平台管理员开启「系统设置 → HTTP 调试与 A2A 文件 → 允许 HTTP（仅调试）」时，该全局授权可满足上述 HTTP 确认门槛，无需逐连接再次勾选。管理员开关仅作用于当前请求和执行策略，不把部署或固定修订中的 `allowUnsafeHttp` 改成 `true`；关闭后，没有独立显式同意的 HTTP 调用重新拒绝。HTTP 风险提示、私网主机白名单、SSRF 和凭据边界仍保留。

## 安全边界保持不变

支持 HTTP 不等于允许任意目标。私有地址须在「管理后台 → 系统设置 → 私网主机白名单」批准；该列表与 SSH 共用，由 `network.privateHosts` 或未被覆盖时的 `TOOLPLANE_PRIVATE_HOSTS` 提供。显式保存空列表可拒绝全部私网目标；恢复默认重新使用环境变量或内置空列表。localhost、回环、链路本地/云元数据和其他受限地址仍被拦截。DNS 解析校验与固定、请求同源限制及禁止重定向保持不变。

端点 URL 不能包含用户名、密码、查询参数或片段。现有查询参数例外仅限 SSE 服务返回的同源会话 POST 地址。

这是一项针对显式配置 HTTP 端点的兼容功能，不会在 HTTPS 失败后自动降级到 HTTP。Sandbox OAuth 默认仍要求 HTTPS；管理员的全局 HTTP 调试设置可放宽本平台的协议要求，但不放宽 OAuth 的客户端、重定向、PKCE 和令牌权限校验，也不能绕过第三方 OAuth 服务或浏览器自身的安全限制。

## 协议校验与执行归属

连接就绪校验认证、MCP 握手和所声明的工具目录，不调用业务工具；它只能证明当时的协议可用性，不保证所有业务操作成功。

Agent 与 Assistant 的每个 MCP 绑定（`AgentServer` / `ChatAssistantMcpGrant`）始终跟随部署工具目录，`allowedToolNames` 由服务端写入全部目录工具名。工具访问权限仅在 MCP 部署的 Tools 页选择，并统一作用于所有已连接的 Agent 与 Assistant；绑定设置只选择部署，不单独筛选工具。添加 MCP 时不需要发现回执或审阅。启动部署、打开工具页或远程会话列工具时会刷新目录；目录、暴露策略或连接配方变化后，`src/lib/process/mcp-grant-sync.ts` 更新绑定，并为当前修订中已有该 MCP 的 Agent/Assistant 自动发布只刷新 MCP 授权的新修订（未应用的其他草稿改动不会被发布）。工具描述或 Schema 变化不再暂停工具，也没有重新批准流程。

已有会话仍固定在原修订，新工具不会自动进入；控制台在旧会话顶部提示“更新到最新版本”，确认后原地切换到当前修订（保留消息、Pi 历史和会话文件，Agent 会话下一轮以新工具集重启宿主）。新会话直接使用当前修订，并在空白页提示本次修订新增或移除的 MCP 工具。工具改名按“删除旧的 + 新增一个”处理。

Assistant 只接受真实远程端点，拒绝 stdio 配方与 ToolPlane Agent/A2A 网关。Agent stdio 通过 `src/lib/process/session-mcp.ts` 运行于加固的 Docker 侧车，身份绑定工作区、Agent、固定修订以及 Conversation 或 A2A context。不同会话不共享可写进程或缓存，默认不挂载 Agent 工作卷；仅投递配方显式环境变量和只读受管配置。`stopSessionMcp` 停止该会话侧车，不删除会话工作文件。

Assistant 对已授权的 MCP 工具直接执行，不再逐次要求用户同意；会话界面只展示工具输入、执行状态、结果和错误。执行前仍取固定修订与实时授权的交集，并检查工作区、操作人、停止状态及运行租约。工具许可列表为空时不会向模型提供工具，也不会因免确认而扩大权限。

每次调用先提交不可重放的执行记录，再向远端派发；取消或连接中断不代表远端副作用已回滚，结果未知时保留 `execution_unknown` 并禁止自动重放。升级迁移 `20261103030000_chat_automatic_tool_execution` 保留旧审批历史，终止仍等待旧审批的 Run、释放会话，但不执行旧请求。旧的逐次批准接口已移除；部署迁移须先排空旧应用，再按单所有者流程重启。

stdio MCP 可在 MCP 详情页「设置 → 运行位置」开启「在智能体沙箱中运行」（`installCfg.runInAgentSandbox`）。这是实时部署设置，不改变定义校验和或已捕获镜像，也不发布新修订；各会话的下一次 MCP 请求按新位置启动侧车，并停止另一位置的旧侧车。开启后会话侧车仍使用已捕获的不可变镜像，但加入该会话沙箱的网络与进程命名空间，以沙箱用户身份挂载会话工作卷到 `/workspace` 并以其为工作目录，根文件系统不再只读。这是用户显式授权的例外：MCP 环境变量（含凭据）对 Agent 可见，MCP 可读写全部会话文件；开启时界面会提示。需要持久数据的 MCP 应把数据路径指向 `/workspace`（如 Memory 的 `MEMORY_FILE_PATH=/workspace/memory.jsonl`）。

会话目录直接读取实时 MCP 进程，并校验启动代次、限制分页与按实际启动秘密脱敏。会话进程 ID 不是 Deployment 主键：不会把目录写成共享部署快照，也不会因找不到 Deployment 行而丢弃成功读取的目录。发现和调用仍逐次求固定授权与实时工具名许可的交集。

Agent 连接检查通过 `src/lib/process/agent-mcp-inspection.ts` 的 `inspectAgentMcpConnection` 完成。在准备制品或读取秘密前，检查活动 owner/admin、当前已应用的 Pi 修订及默认沙箱；共享连接无需已启动。每次检查创建一次性、可按来源排空的独立进程，使用已准备的不可变配方与该连接专属凭据，不挂载 Agent 工作卷，只进行受控握手和有界 `tools/list`。进程停止并清理后，才对仍为当前目标的状态原子写入脱敏目录、配方及文件校验和，并触发上述授权同步。

Agent 修订准备先要求准确的 npm/PyPI 版本或 Git commit，再把完整已安装依赖树捕获为不可变本地 Docker 镜像。捕获使用加固的非 root 容器，不注入用户凭据、Agent 文件、受管配置或平台秘密；只安装依赖，不启动 MCP 服务或调用业务工具。Docker 配方不启动服务即生成快照。发布事务只检查已审核镜像 ID 与来源标签；捕获失败或定义变化不会替换活动修订。会话直接执行捕获的二进制，不运行 `npx`/`uvx` 或联网重装依赖。镜像保留供修订回滚，缺失时要求显式重新准备，不静默重建。每次调用同时复核配置文件密文身份、实时逐 Agent 工具授权与修订归属。配方变化必须发布新授权修订，凭据轮换不将秘密值写入修订。

修改共享配置或凭据时返回受影响的 Agent 与 Assistant ID，并要求对重新计算的集合明确确认；安装能力包不得修改既有共享连接。

远程配置编辑仅为完全相同的已批准端点保留明文风险许可；切换到另一个 HTTP URL 必须重新明确确认。固定远程调用与共享连接编辑串行，并核对实际运行远程客户端的私有身份（包含已解析凭据值），而非仅信任展示标签。

会话 stdio 与远程调用在每次幂等启动后、工具发现后再次使用进程私有 HMAC 比较新解析凭据与实际进程身份。轮换或删除凭据（包括可选键）不会让旧进程继续以新配置获权；身份缺失或不匹配时，在业务 RPC 前返回 `MCP_CONNECTION_RESTART_REQUIRED`。比较密钥与 MAC 仅在进程内存，不写注册表、日志或外部响应，也不自动重启或回退凭据。

远程身份比较密钥与 supervisor 启动记录具有相同的进程生命周期，跨路由 bundle 实例和开发模块重载保持一致，不按请求或模块实例重新生成。密钥生命周期切换前创建的进程必须明确停止后重新启动；不会静默重签身份，也不回退到无密钥摘要。

明确修改连接凭据／配置、变更文件秘密、停止、重启或删除连接时，在提交变更前排空该来源的全部会话侧车。来源关联先于启动入队登记，因此排队中的启动也会停止；容器或私有配置投影清理失败会阻止持久化变更。其他来源及会话工作卷不受影响。会话 RPC 与连接变更共用来源生命周期锁，防止停止与提交之间启动旧凭据进程；后续获授权请求可使用新凭据创建新的会话侧车。

受管文件更新在停止健康进程前，先拒绝已可确定的总文件数／总字节数超限；排空后的串行化持久化事务再次执行同一限制检查，防止并发文件变更绕过限制。停止／强制停止不等待来源侧车清理或排队的数据库写入才向当前进程发信号；调用方仍需等待全部关联清理完成，任何清理失败都禁止持久化新秘密。

启动协调不恢复绑定旧 Agent runtime 的部署，也不调用旧运行时就绪回调；这些容器只保留受控停止／排空与历史文件处理用途，普通非 Agent MCP 的恢复不受影响。

生成启动配置时，保留的旧 Agent runtime 配方直接返回 `AGENT_RUNTIME_RETIRED`，不会降级成普通 Docker 沙箱。监督器不再生成旧运行时令牌、模型配置或专用启动／就绪参数；绑定历史资源的停止与显式删除清理仍独立保留。
